## 1. 已确认的口径

1. 专业变体由教师自行配置，形式是章节目录的选择。例：机电选前 7 章，材料化工只要前 5 章。
2. 课程接口只做「形式类」：一张课程关系图 UI，节点可配置外链，点击跳转。
3. 智能体只做两个：学生端（问答、学习、知识点）、教师端（监管、统领全体学生进度）。
4. 不考虑时间约束，按内容质量与可维护性推进。
5. **功能必须覆盖「图 2」的完整教学流程：课前准备、课堂实施、课后跟进，以及诊断—学习—反馈—改进的闭环。功能要足，不能只做答疑和进度。**

---

## 2. 系统定位

一个网页应用，两个入口。

- **学生端**：按专业看到对应章节 → 预习、上课、做作业与实验 → 问智能体 → 按薄弱点补练 → 看自己的知识图谱与学习路径。
- **教师端**：配置专业变体 → 发诊断与任务 → 组织课堂（分组、快测、干预）→ 批改与复盘 → 看学情、出报表、得到教学改进建议。

课程对象：《电工技术》，48 学时 / 3 学分 / 大二本科。

三翼能力模型（贯穿内容标注）：设计翼 = 问题识别与方案构想；工程翼 = 分析建模与实验验证；管理翼 = 流程组织、规范表达与团队协作。

### 3.4 完整教学闭环

图 2 底部的闭环 **诊断 → 学习 → 反馈 → 改进**，对应到系统的数据流：

| 环节 | 系统里由什么产生 |
| --- | --- |
| 诊断 | 诊断测评、课堂快测、作业与实验数据 |
| 学习 | 预习任务、章节资源、小组讨论、实验实践 |
| 反馈 | 自动批改、错因归因、智能体答疑、AIGC 实验分析 |
| 改进 | 个性化补练、即时干预、教师教学调整、资源迭代 |

闭环的产物是**学生画像 + 班级学情**，向上支撑教师的改进决策，向下驱动学生的路径调整。全周期数据靠事件埋点采集，这是「数据驱动持续改进」这条主线的落地方式。

### 3.5 持续迭代

图 2 左侧的虚线回路（持续迭代）：每一轮教学结束后，数据回流形成两类建议——

- **资源迭代建议**：哪些资源学生看不完、哪些例题正确率异常、哪些知识点缺案例
- **教学策略建议**：哪个环节耗时过长、哪个知识点连续多届薄弱、哪种干预有效

这两类建议由教师端智能体定期生成，教师确认后落到下一轮教学。

## 4. 两个智能体的设计

### 4.1 学生端智能体（学习助手）

- 贯穿全流程：课前做预习导学与概念答疑；课中提供讨论提示与快测解析；课后做作业答疑、错因归因、实验复盘解读、补练推荐。
- 知识来源：课程知识库（四类资源 + 教材章节 + 题库解析）
- 回答策略：分级提示——反问澄清 → 给方向 → 给步骤 → 最后才给答案，不直接给答案
- 权限边界：只能访问本人数据 + 公共课程内容

### 4.2 教师端智能体（监管总管）

- 贯穿全流程：课前生成诊断卷 / 导学单 / 教学目标；课中归纳共性问题、解读快测结果、列出需干预名单；课后汇总错因、生成复盘讲评、出学情报告与教学改进建议。
- 知识来源：全班学习数据 + 课程知识库 + 统计查询工具
- 三项能力：
  1. **查**：结构化查询——「哪些学生第 3 章没完成」「哪个知识点错得最多」必须查库返回名单，不是空泛描述
  2. **看**：学情分析——班级 / 专业 / 章节 / 知识点多维视图，落后预警
  3. **写**：生成——测验题、导学单、讲评稿、学情报告、周报月报
- 权限：教师角色，可读全班数据

### 4.3 与申报书的对应关系

申报书原文写的是「1+5+1」共 7 个智能体，再加督导与管理层。你定的是 2 个入口，这是落地精简版。

建议做法：对外只呈现两个入口，底层保留「按模块配置检索范围」的能力，让 5 个模块各自检索自己的内容。开发量不增加，结题时也能对回申报书里「1+5+1」和「督导管理」的描述。

## 5. 专业变体配置

教师端提供章节勾选器：为每个专业勾选可见章节目录。

- 例：机电专业 → 第 1–7 章；材料化工专业 → 第 1–5 章
- 随时可调，调整后学生端立即生效
- 与分层推送联动：同一章节内，不同专业可按掌握度拿到不同难度的资源

## 10. 开发顺序（按依赖关系）

1. 内容规范与数据模型定稿：章节、知识点、四类资源、专业变体、题库结构
2. 基础框架：登录、角色区分、课程地图、章节学习页
3. 专业变体配置器 + 按专业过滤内容
4. 诊断测评 + 知识点掌握度 + 个人知识图谱
5. 任务发布与预习导航
6. 学生端智能体：知识库入库、对话、分级提示、对话留痕
7. 作业与错题归因
8. 课堂快测（实时）+ 教师大屏
9. 小组讨论与协作记录
10. 实验复盘（文件提交 + AIGC 分析 + 过程溯源）
11. 个性化学习路径与补练
12. 教师端学情总览 + 教师端智能体（查 / 看 / 写）
13. 课程关系图展示与编辑
14. 闭环报表、教学改进建议、打磨与部署

**两个地基**：章节内容是一切的地基；题库是第二个地基——诊断、快测、作业、补练全都依赖它。这两样先立住，后面的功能才不是空壳。

**一个工程注意点**：课堂实施部分（快测、小组）是上课时现场使用的，对实时性和稳定性要求最高，手机端体验必须优先做好。

- 学生端章节页可查看本节练习与答案
- 基础诊断测评：选范围自动组卷（仅客观题）→ 答题 → 自动判分 → 知识点与章节掌握图谱 → 错题回顾
- 学生端「我的学习状况」：历次测评记录与知识点累积掌握情况
- 教师端「诊断学情」：薄弱知识点排行与测评记录汇总（当前为本机数据）
- 课堂快测：一键发起生成课堂码 → 学生输入码作答 → 提交即判分并看解析
- 教师端实时统计：已提交人数、平均正确率、每题选项分布与正确率
- 投屏讲评模式：大字号逐题展示选项分布、正确答案与解析
- 课堂快测数据通过浏览器跨标签页实时同步（同一台电脑可完整演示教师大屏 + 学生答题）
- 分层资源推送：按知识点掌握度分为巩固 / 提升 / 拓展三层，自动匹配对应节的例题、易错点、案例与配套练习
- 分层规则可配置：巩固线、掌握线、A 型专业上浮幅度，均可在教师端调节
- 推送能力覆盖统计：知识点总数、有章节资源、有练习题、资源与题目齐全
- 预习导航：教师发布任务与学习目标、设置截止时间、按章勾选范围、可去掉单节
- 一键生成导学单：自动拼装任务范围、学习目标、各节知识点与例题、相关思考题，可复制导出
- 学生端预习任务：看目标与要求、逐节标记完成、提交预习疑问；教师端可查看学生疑问
- 作业辅导：教师按章节布置作业 → 学生在线作答提交 → 客观题自动判分 → 错因归因到知识点
- 错因分三类：知识性（该知识点掌握度偏低）、方法性（基本掌握但答错）、粗心（难度低且同知识点其他题答对）
- 错题本：累计所有作业错题，按知识点标注错因并附解析
